# 0002. バージョン付き中間スキーマをテーマ向けの公開コントラクトにする

## 状態

採用

## 文脈

[ADR 0001](0001-cosense-api-knowledge-confined-to-core.md) で Cosense API の知識を `core` に隔離した
以上、`core` の外側 — 特にサードパーティ製テーマ — が何を頼りにしてよいのかを明示する必要がある。
「`core` が返すオブジェクトの形」が暗黙のコントラクトのままだと、内部リファクタのつもりの変更が
テーマを壊す。

## 決定

`packages/core/src/schema/v1/` に zod スキーマとして中間モデルを定義し、これを**公開コントラクト**と
位置づける。

- 各ページは `schemaVersion: "1"` を持つ
- スキーマは `@cosense-site-kit/core/schema` から re-export し、テーマはこれだけを消費する
- **pre-1.0 の間はこのスキーマも予告なく破壊的に変更する**（`schemaVersion` を据え置いたまま形を変える
  ことがある）。「v1 を凍結し、破壊的変更は v2 とマイグレーションヘルパを並べて行う」のは 1.0 以降の約束

## 影響

- テーマ作者に対して「触ってよい面」が型として提示される。`docs/THEMES.md` の記述もこのスキーマを軸に書ける。
- pre-1.0 では安定を約束しないため、テーマ側は本体のバージョンに追従する前提になる。この割り切りが無いと
  スキーマの形を直せないまま 1.0 を迎えることになる、というのが選択の理由。
- `zod` による検証がビルド時に効くので、ソース側の想定外データはテーマではなく `core` の境界で落ちる。
- 「テーマが生データを覗きたい」ケースはスキーマへの項目追加として扱う。抜け道は作らない。
